# Project History — `dlp-demo`

A reconstructed history of the Data Download Prevention POC ("Data Export Portal"): where it
started, the Databricks connection it runs on, how it evolved, and the current state.

> The git repository has no commits yet, so this history is reconstructed from the seed design
> documents in the repo, the current file tree, and the build conversations. Treat it as a
> narrative changelog rather than a commit log.

---

## 1. Seed documents (design inputs)

The project was generated from four hand-authored documents still in the repo:

| File | Role |
| --- | --- |
| `databricks_poc_spec.md` | Original POC spec. Targeted **Streamlit** with a *simulated persona toggle* and `restricted/approved/governed/export_outputs` schemas. |
| `BDC_Databricks_Demo_Setup.md` | Domain/context: NHLBI BioData Catalyst × dbGaP/RAS, GA4GH passport tokens, ABAC tags, row filters, column masks, DAR expiry, `system.access.audit`. |
| `Databricks_Access_Control_Checklist.md` | Environment setup checklist ("compute allowed, exfiltration blocked"); real enforced controls vs workarounds (Free Edition vs Sandbox). |
| `docs/SPEC.md` + `docs/TEST-PLAN.md` | The living functional spec, rewritten as the app evolved. `docs/SPEC.md` is the authoritative description of the final architecture. |

**Key early pivot:** the original spec called for *Streamlit + a persona toggle*. The actual build
was done on **AppKit (Express + React/TypeScript)** with **real Unity Catalog enforcement** instead
of a simulated toggle.

## 3. Connection

- **Workspace host:** `https://dbc-e2647759-e2ba.cloud.databricks.com` (`databricks.yml`, `.env`).
- **Compute:** Serverless SQL Warehouse, id `69e7e6f0afe612c9`, attached to the app as a bundle
  resource (`CAN_USE`).

  - **App service principal** (`f359d298-69b8-4fb5-ae24-46eda7fe60a8`) for writes to app-owned
    tables and for artifact generation.
- **Local dev:** `.env` (`DATABRICKS_HOST`, port) copied from `.env.example`.
- **Deploy:** `databricks bundle deploy -p artdscs` → `databricks bundle run app`; live at
  `dlp-demo-632756915321315.aws.databricksapps.com`.

## 4. Data layer

`sql/001_governance.sql` is the single migration establishing the **`governed.default`** schema:

- **Tables:** `export_requests`, `audit_events`, `study_catalog`, `user_dbgap_permissions`.
- **Views:** `export_decision` (self-scoped by `current_user()`), `export_decision_all` and
  `steward_queue` (row-filtered to `bdc-stewards`), `audit_events_scoped`.
- **Grants:** to the `bdc-analysts` / `bdc-stewards` **account groups** (never individuals).
- **Artifacts:** a `governed.export_outputs` schema for per-request governed Delta tables.
- **Seed:** demo permission rows so real `current_user()` evaluation shows both granted and denied
  outcomes.

Nine analytics queries live in `config/queries/` (`*.obo.sql` = OBO, `*.sql` = service principal).

A second migration, `sql/002_mock_consent_grants.sql`, adds a **mock dbGaP/Fence consent-grants
layer** in its own catalog **`bdc_governance.dbgap_sync`**: a hand-seeded `user_consent_grants`
table (`source = manual_seed_no_fence_access`), a real `has_active_consent()` row-filter UDF, and a
consent-gated `governed.default.framingham_cohort` (with a `_consents_` column) the filter is applied
to. Only the grant *data* is mocked; the enforcement is real.

## 5. Evolution (in rough order)

| Phase | What changed |
| --- | --- |
| Base → governed tables | Switched the app to read/write `governed.default.*` tables. |
| **Real enforcement (Tier 1/2)** | Removed client-side role simulation; identity from forwarded proxy headers; UC account-groups; OBO reads; server-side re-validation on writes; self-enforcing `export_decision` view; real `system.access.audit` panel; real egress checks (results-download setting, IP access lists). |
| `poc_role` semantics | Group membership is the source of truth; `poc_role` mirrors it (highest role wins) via `scripts/sync_poc_role.sh`. |
| Identity robustness | Fixed steward badge falling back to "Analyst" on OBO failure; added `IdentityProvider` with retry/backoff; fixed a string-vs-boolean `is_steward` bug. |
| Role-based audit | `audit_events_scoped` view + steward-only audit visibility. |
| Data file preview | `/api/study-files` + preview endpoints over UC volumes; `DataFilePreview` with paging + row counts. |
| **Export-path hardening** | Approval mints a real per-request governed Delta table in `export_outputs` (CTAS from `read_files`, UC lineage + provenance tags); app-mediated, expiring, re-validated downloads; raw table never granted to users. |
| Analyst UI changes | Audit made steward-only; Home explore links → collapsible sidebar; Submit page horizontal notice + side-by-side preview; auto-detected format. |
| Framing / copy | Clarified the app runs **downstream** of dbGaP/DAC; added `/about` page, per-page "How Unity Catalog enforces this" callouts, decision-maker positioning. |
| Steward details modal | Enriched `steward_queue` view + modal (requester, live DAR decision, request details). |
| **Data-freshness fix** | Root-caused a 1-hour analytics cache; added uncached OBO live endpoints `/api/steward-queue` + `/api/my-requests` and a `useLiveResource` polling/refresh hook. |
| **BDC-inspired enhancements (#1–3)** | (1) Consent columns (`_consent_group`, `_dbgap_accession`, …) appended to every exported row + artifact tags; (2) "Credentials: no token to leak" contrast on `/about`; (3) Query-ID / cohort pointer — variable selection + a safe structured row filter stored as JSON and applied/re-validated at approval, surfaced in Submit (Query ID), My Requests, and the steward modal. |
| **Access Decisions page removed** | Dropped the `/access-decisions` page and its interactive Exfiltration Controls panel (plus the orphaned `/api/exfil/*` routes) as not useful to the POC. The egress/download boundary is still re-validated server-side at download time (`downloads_disabled` check reuses the same workspace-state helper). |
| **BDC reframing (beneath, not beside)** | Repositioned Unity Catalog as a consent-group-aware governance layer *beneath* BDC's tools (PIC-SURE / Seven Bridges / Terra) rather than a sixth environment beside them. Acknowledged BDC's real project-level dbGaP re-check and framed the gap as **granularity + egress coverage**. Named the three egress paths — direct download / CLI, external cloud Volume copy, SBFS mount (2–3 stubbed "coming soon"). Added consent-group badges to the steward queue, an **Egress path** column to the audit log (with a SQL `TODO` to promote `egress_path` to a first-class `audit_events` column), egress-path labels on My Requests, and an honest **scope-limit note** on `/about` + the Activity Log. |
| **Mock consent-grants layer** | Added an explicitly-labeled stand-in for a Gen3/Fence → dbGaP grant sync we have no API access to: `sql/002_mock_consent_grants.sql` creates `bdc_governance.dbgap_sync.user_consent_grants` (hand-seeded, `source = manual_seed_no_fence_access`), a **real** `has_active_consent()` row-filter UDF, and a consent-gated `governed.default.framingham_cohort` (new `_consents_` column) the filter attaches to — verified allow (alice/bob), revoked-deny (carol), wrong-tag-deny (dave). Flagged (not papered over) that no `_consents_`/Framingham table pre-existed. New **Consent-Gated Data** page (`/consent`) + uncached OBO route `/api/consent-demo` show the caller's row-filtered view and the seeded grants under a prominent *"manually seeded (no Fence API access)"* label. |
| **Export-path explainer** | Replaced the functional **Download** button on My Requests with an educational dropdown of four Unity Catalog export paths (D2D Delta Sharing, Lakehouse Federation, Iceberg / UC REST API, Volumes), each with an inline explanation and a shared *"all four paths stay inside the same FedRAMP authorization boundary — none produce a raw file export"* note. The real file-download control was removed from this UI element. |
| **Platform audit reliability** | The `system.access.audit` panel was intermittently showing an empty/failed state because the query routinely exceeds the 30s warehouse `wait_timeout` on a cold start. Added a polling execution helper (`executeStatementWithPolling`, `on_wait_timeout=CONTINUE` + `getStatement` polling) behind an uncached OBO endpoint `/api/platform-audit`, and switched the panel from the cached analytics query to the `useLiveResource` hook with a **Refresh** button — surfacing the real error instead of a silent empty state. |
| **UI trims for the presentation** | Removed the egress-path badges from My Requests and the **Egress path** column from the app audit table (kept the export-path dropdown; `egress_path` is still recorded in audit `details`). Removed the **Consent-Gated Data** page (`/consent` + `/api/consent-demo`) — the underlying mock consent SQL layer in `sql/002_mock_consent_grants.sql` is retained. Removed the **About** page (`/about`) and its governance-chain / no-token / enforcement-layer panels; that narrative now lives in the presentation. The scope-limit note remains under the Activity Log. |
| **External recipient mock for export paths** | Turned the educational export-path dropdown into a request-shaped, clearly **Simulated** preview of how a platform *outside* Databricks would consume the governed artifact. Each of the four paths gained a **BDC-fit** tier (Federation + Volumes "Most aligned"; Iceberg/UC REST "Also strong"; D2D Delta Sharing "Narrower fit") and a best-fit BDC consumer label, plus a **Preview recipient view** dialog with a "connection recipe" snippet (federation SQL / `databricks fs` / `curl` credential-vend / `delta_sharing` client) and a simulated recipient result, shaped by the request's dataset, consent group, columns, and artifact table. No cross-platform call is made. `/api/my-requests` now also returns `output_table` + `consent_group` (via a `study_catalog` join) to fill in the snippets. |

## 6. Working process

The loop used throughout:

1. Edit `server/server.ts`, `client/src/App.tsx`, and/or `sql/001_governance.sql`.
2. `npm run build` (server: `tsc` + `tsdown`; client: `tsc` + `vite`).
3. Apply SQL changes via the Statement Execution API on warehouse `69e7e6f0afe612c9`.
4. `databricks bundle deploy -p artdscs` → `databricks bundle run app`.
5. Verify in the running app; keep `docs/SPEC.md` in sync as the authoritative spec.

## 7. Current state

A Unity-Catalog-native governed export portal:

- Forwarded-identity auth (no token hand-off) and group-based roles.
- Self-enforcing, `current_user()`-scoped decision views.
- OBO reads with server-side re-validation on every write.
- Approval still mints a real, expiring, tagged governed Delta artifact (raw tables never granted to
  users; the app is the only path to the bytes). In the UI, the My Requests download control is now
  an **educational dropdown** of Unity Catalog export paths (Delta Sharing, Lakehouse Federation,
  Iceberg / UC REST, Volumes), each ranked by BDC fit and backed by a request-shaped, clearly
  simulated **recipient-view** dialog that mocks how a platform outside Databricks would consume the
  artifact — rather than a raw file export.
- Dual audit (app-written `audit_events` + platform `system.access.audit`); the platform panel reads
  through an uncached polling endpoint with a **Refresh** button so slow cold-warehouse queries
  resolve instead of showing empty. `egress_path` is still recorded in app-event `details` (the audit
  UI column was removed).
- A cohort-pointer submission model (Query ID) with consent metadata carried into the exported data.
- A consent-group-level SQL layer: a real UC row filter (`has_active_consent`) gates
  `framingham_cohort` per caller, driven by a mock (but explicitly labeled) hand-seeded grants table
  standing in for a Fence/dbGaP sync. The dedicated `/consent` UI page has been removed; the SQL
  layer remains.
- Positioned as a consent-group-aware governance layer **beneath** BDC's tools (not beside them),
  enforcing across three egress paths (direct download today; volume copy + SBFS mount planned), with
  a stated scope limit — it governs what can be *exposed*, not data that has already left the
  platform. The scope-limit note is still shown under the Activity Log; the dedicated About page was
  removed and that framing now lives in the presentation deck.

Deployed as an AppKit app on Databricks Apps.
